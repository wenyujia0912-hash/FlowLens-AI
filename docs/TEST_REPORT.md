## 已验证的真实集成场景（阶段3-7开发过程中执行，未写成自动化测试但有实际执行记录）

以下场景通过手动脚本对真实种子数据库（340订单/15异常）执行验证，结果记录在各阶段的交付报告里：

- 异常扫描 → AI诊断 → 人工修改风险等级 → 创建任务 → 异常状态变为"处理中" → 完整闭环
- 任务创建 → 处理中 → 追加处理记录（3条）→ 完成（填写结果）→ 日志时间线正确保留全部6条操作记录
- 数据库未初始化场景在全部5个页面的真实执行（通过模拟streamlit API）
- 跨天场景下种子数据的时间基准正确性（在2026-11-03和2026-11-04两个不同日期分别生成验证）
- 导出数据行数与数据库真实记录数的逐项比对

## 未覆盖的部分（如实列出，不隐瞒）

1. **真实浏览器渲染和用户交互从未被测试**。所有页面级验证都是通过最小化模拟的streamlit API执行页面代码逻辑，验证的是"数据调用链不报错"，不是"UI在浏览器里的实际呈现和交互手感"。这是因为开发环境无法安装`streamlit`包（网络受限）。
2. **Streamlit的`st.form_submit_button`在模拟环境里固定返回False**，这意味着"表单提交→触发service调用"这条连接路径本身，从未在页面上下文里被自动化验证过——我们是单独调用service层函数验证了行为是对的，但"点击提交按钮确实会调用到这个函数"这一步，依赖真实Streamlit运行时才能验证。
3. **真实LLM API集成未测试**（因为未实现，`model_type="real"`当前设计为直接报错）。
4. **Excel导出文件未经真实Excel/Numbers应用打开验证**，只验证了ZIP/XML结构的有效性和macOS系统级的文件类型识别（`file`命令识别为"Microsoft Excel 2007+"）。
5. **并发场景未测试**（例如两个用户同时创建任务、同时扫描异常）。SQLite本身支持基本的并发写入，但没有专门测试这个场景。
6. **大数据量下的性能未测试**。当前测试规模（340订单/15异常）运行流畅，更大规模数据下的查询性能未验证。
7. **数据生成规模的边界未系统性测试**（例如0条订单、1条订单的极端情况，只测试了"空数据库"这一种极端场景）。

## 如实的样本量说明

上述"规则识别准确性100%"等百分比，统计样本来自开发阶段人工设计的测试用例（通常每种规则2-5个case），不是大规模生产数据的统计结果。如果用于正式场合的汇报，应明确说明这是"单元测试通过率"，不应该被解读为"生产环境下的规则准确率"或"AI诊断的实际可信度"。
