# FlowLens AI 演示脚本（5-8分钟）

## 演示前准备

```bash
python -m database.seed_data --force   # 确保有干净的演示数据
streamlit run app.py
```

> 注意：种子数据的时间基准是动态的（相对"今天"计算），所以每次生成的具体异常ID、订单编号都不同。本脚本不依赖任何固定ID，演示时在列表里按描述选取即可，这正好也能体现规则引擎是在真实数据上实时判断的，不是放了几条写死的演示数据。

---

## 第1步：驾驶舱总览（约1分钟）

打开应用，默认进入**运营驾驶舱**。

**讲解要点**：
- 指向5个KPI卡片："订单总量、异常订单数、待处理异常、履约完成率、逾期任务数——这些数字不是写死的，全部来自数据库实时查询。"
- 点击"异常订单数"卡片，页面跳转到异常中心并自动带入筛选——"点击任何一个KPI都能直接跳到对应的明细列表，不是孤立的数字展示"。

---

## 第2步：异常发现（约1.5分钟）

在**AI异常诊断中心**列表视图：

1. 点击顶部"🔄 扫描新异常"按钮。
2. **讲解要点**："这一步跑的是规则引擎，不是AI——5条判断规则（超时未发货、物流延迟、履约超时、供应商备货异常、订单状态冲突）都是确定性的时间/状态比较，不依赖大模型。"
3. 指出扫描结果提示："发现XX条新异常，XX条因为已存在而跳过——这个去重机制保证同一个问题不会被重复开出好几条异常记录，哪怂天天跑扫描都安全。"
4. 在列表中选一条 **风险等级=高、状态=待确认** 的异常（建议选"超时未发货"类型，叙事最直观），点击"详情"。

---

## 第3步：异常详情——已知事实（约1分钟）

进入详情页，**讲解要点**（逐区指出）：

- **📋 已知事实**区：指出具体字段值（例如"预计发货时间=X，当前时间已经是Y"）——"这部分是数据库里的真实数据，不经过AI加工，我们随时能验证它。"
- 展开"查看订单/客户/供应商/物流完整信息"，指出客户等级（例如"战略客户"）——"同样的异常，客户等级不同，处理优先级应该不一样，这是下一步AI分析要考虑的。"

---

## 第4步：AI诊断——客户影响评估与建议（约2分钟，核心环节）

点击"▶️ 运行AI诊断"。

**讲解要点**：
- "点下去之后，调用的是我们自己定义的Mock AI——当前没有接真实大模型，这是故意的选择：业务闭环先用确定性强、成本为零的方式跑通，真实LLM接入是预留好接口、随时可以换的。"
- 诊断结果出现后，**逐区讲解**：
  - **🤖 AI诊断**区：指出"摘要"，然后展开"可能原因"——"每条原因后面都标了置信度，中或低，这不是AI在装自信，是明确告诉你这是推测，不是结论。"
  - 指出"客户影响分析"——"这里会结合这是不是重点客户来说明影响程度。"
  - **✅ 建议操作**区：勾选1-2条建议——"这些建议默认不会生效，必须我手动勾选才算'采纳'，而且采纳了也只是把它写进任务描述里，AI不会自己去执行任何动作。"
  - 指出"沟通参考文本"——"这是给运营人员用的草稿，不会自动发给客户。"
  - **❓ 待核实事项**区："这些是AI主动说'我没把握、你需要自己去核实'的信息，故意不让它看起来像确定的事实。"

---

## 第5步：人工确认与任务创建（约1.5分钟）

在"修改风险等级"展开区，演示可以手动把风险等级从规则给的初始值改成别的——**讲解要点**："规则引擎给的是初始评估，AI只能建议，但最终拍板的是人，风险等级随时可以人工改。"

滚动到"创建运营任务"表单：
- 标题已经预填好（基于异常类型和订单号）
- 描述字段会带上刚才勾选采纳的建议
- 填写负责人、优先级、截止日期
- 点击"确认创建任务"

**讲解要点**："提交之后系统会做两件事：创建任务、把这条异常的状态改成'处理中'——注意这个状态变化是我提交表单这个动作触发的，不是AI自动做的。"

页面会自动跳转到**运营任务中心**，直接定位到刚创建的任务。

---

## 第6步：任务处理闭环（约1分钟）

在任务详情页：
1. 点击"标记为处理中"
2. 在"追加处理记录"填一句话，保存
3. **讲解要点**："处理记录是追加式的，历史记录永远保留，不会被覆盖。"
4. 滚动到"完成任务"表单，**故意先不填处理结果直接提交**——指出报错："完成任务必须填写处理结果，这个校验在业务层和数据库层各做了一遍，就算有人绕过页面直接操作数据库也拦得住。"
5. 填上处理结果，提交成功。

---

## 第7步：回到驾驶舱和分析页，验证数据联动（约1分钟）

返回**运营驾驶舱**——指出"逾期任务数"或"待处理异常"的数字已经变化（如果刚才处理的任务影响了这些指标）。

进入**运营分析**页的"任务分析"Tab——指出"任务完成率"已经反映刚才的操作。点击"查看任务明细"展开，再点"导出Excel"下载——**讲解要点**："这个导出是真实生成的.xlsx文件，字段和刚才页面上看到的明细完全一致。"

---

## 收尾（约30秒）

回到"AI异常诊断中心"，再点一次"扫描新异常"——**讲解要点**："再扫一次，刚才处理过的这个问题不会被重复创建成新异常，因为规则引擎的去重逻辑是基于'同订单同规则在活跃状态下唯一'，这个机制在测试里验证过，重复扫描N次都不会炸出重复记录。"

---

## 备用环节（时间充裕时可加）

- 在**客户与订单**页，点开刚才那个异常关联的客户详情，展示"关联订单数""关联异常数"是从数据库现算的，不是写死的汇总数字。
- 在**运营分析**的"异常分析"Tab，展示"重点客户异常情况"——哪些客户异常最多。

## 注意事项（给演示者自己看，不用念出来）

- 如果想要一个"干净"的异常用来演示（还没被诊断过），优先选状态=待确认、还没有关联任务的那条。
- 完成任务那步"故意不填处理结果"的报错演示，是在展示系统的硬约束，不是bug，讲解时可以说清楚这是设计出来的。
- 全程不需要配置任何API Key，AI_MODE默认就是mock，完全离线可跑。
